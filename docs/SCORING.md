## 3. 目标设计：独立纯函数模块（第 1 步已落地）

`src/utils/scoring.js`（307 行，纯函数、无 React、无网络、随机源可注入）已在 `main`，联机服务端就绪后**原样搬入服务端**。已导出的能力：

```js
CAP_BASE_MULTIPLIER / BIG_HU_BASE_MULTIPLIER / SMALL_HU_BASE_MULTIPLIER / SEAT_NAMES
birdSeatOffset(value)                      // 1/5/9→0、2/6→1、3/7→2、4/8→3
birdSeat(dealerSeat, bird)                 // 鸟点（或牌对象）→ 绝对座位
capAmount(B) / smallHuBase(B) / bigHuBase(B, k)
countEffectiveBirds(birdValues, dealerSeat, otherSeat)   // 逐家 n
payerAmount({ isBigHu, k, B, F, n })       // → { base, multiplier:n+1, beforeCap, cap, capped, cappedHit, fixed:2F, P }
scoreRound({ method, B, F, dealerSeat, winner|winners, discarderSeat, birdValues })
  // method: 'zimo' | 'dianpao' | 'tongpao' | 'qishou' | 'siji'
  // → { method, B, F, dealerSeat, cap, changes[4], details[], winners[], birdDetail[], zeroSum }
nextDealerSeat({ outcome:'win'|'tongpao'|'draw', winnerSeat, discarderSeat, lastDrawerSeat })
rollBirdDice(count, randomInt)             // 骰子数 = 抓鸟数；随机源由调用方注入（服务端 crypto）
describeBirdHits(birdDetail)               // 「庄位×2 · 对家×1」可读文案
```

每条明细（`details[]`）含：`method, winnerSeat, payerSeat, isBigHu, k, huTypes, base, n, multiplier, beforeCap, cap, capped, cappedHit, fixed, P` —— 满足规格 §九.2「逐家明细（含每家的 n、封顶前后的金额、P）」。

**接线时仍需你确认/注意的 3 个缺口**（不阻塞，但会影响第 2–5 步）：
1. **「该次结算的庄位」在运行时没有现成来源**：`stateRef.current.dealerId` 是**上一局**的庄（终局结算后才 `setDealerId(winnerId)`）。每次结算必须显式传「本次结算庄位」：自摸/点炮 = 胡牌者，通炮 = 放炮者，起手胡/中途四喜 = 触发者。这是 S12 的落地细节，我按此实现（见 §6）。
2. **终局抓鸟仍走 `ML.drawBirds`**（牌墙头部、不移除、只输出 `hitsWinner`）→ 需按 S2 决定「改末尾并移除」，再把它产出的 `{ value }` 交给 `scoreRound`。
3. **UI 层（RRM/SHM）** 需要按新 `details[]` schema 重写渲染（D13）。
