# 长沙麻将 · 界面设计规范（DESIGN.md）

> ROADMAP **P2-2** 的前置产物：**先定规范，再统一改造**。
> 本文只写「已经存在的事实 + 可执行的规则」，不写口号；每条规则都给出**现状取值**（来自代码）与**验收方式**（跑什么、看哪里）。
> 适用范围：`src/App.jsx`、`src/components/*`、`src/*.css`。**不改**牌面 SVG 艺术本身（属重绘，另立任务）。

---

## 1. 设计原则

1. **现代清澈 · 翡翠牌桌 · 象牙骨牌**（沿用现有定位）：牌桌是「皇家红绒 + 金线」的暖色场，牌面是「象牙白 + 翠玉背」的冷色物；两者靠**明度差**拉开层次，不靠花色数量堆装饰。
2. **信息先于装饰**：任何装饰不得抢走「轮到我 / 可胡可碰 / 剩余张数」这三类信息的视觉优先级。
3. **一屏可判**：不允许出现需要滚动才能看全的对局信息（牌桌类应用滚动=失控）。
4. **不改手感**：出牌/摸牌/吃碰杠的点击热区与反馈节奏优先于动画花样；新增动效一律可被 `prefers-reduced-motion` 关闭。
5. **不引 UI 库**：继续用 Tailwind v4（CSS 优先）+ 自有组件，避免为一个项目引入整套设计系统。

## 5. 牌面规范

- **比例 3:4**（`viewBox="0 0 72 96"`），圆角 `rounded-lg`（约 8% 宽）。
- 状态：默认（象牙面 + 翠玉背）/ 选中（抬起 + 金 ring）/ 高亮可操作（翠 ring + `brightness-110`）/ 禁用（`opacity-40`）。
- 牌面数字**必须可辨**：在 32×44 的最小弃牌尺寸下，万字/条子/筒子的识别优先于装饰纹理（P2-2 需逐尺寸看图核对）。
- 牌背：金色底 + 白边（现状），不得出现可辨认的花色信息（防作弊属性）。

---

## 6. 间距 / 圆角 / 阴影

- 间距基线 **4px**，常用档位：`2/3/4/6`（8/12/16/24px）；同一容器内不得混用 5px、7px 这类非档位值。
- 面板内边距：`p-4`（小面板）/ `p-6`（结算、规则页）。
- 圆角：面板 `rounded-xl|2xl`；按钮 `rounded-xl`；胶囊与徽标 `rounded-full`；牌面 `rounded-lg`。
- 阴影三层：`shadow-sm`（贴桌元素）/ `shadow-xl`（胶囊、按钮）/ `shadow-2xl`（弹窗）。

## 7. 动效

| 场景 | 时长 | 曲线 | 现状 |
|---|---|---|---|
| 出牌/摸牌 | 150–200ms | ease-out | `transition-all duration-150` |
| 弹窗出现 | 200–250ms | scale+fade | `fadeIn`/`scaleUp` |
| 分数变动 | 300ms 数字滚动（可选） | ease-out | 未实现（P2-1 体验项） |

**必做**：所有动效在 `@media (prefers-reduced-motion: reduce)` 下退化为即时切换。
**禁止**：阻塞操作的动画（超过 300ms 才能继续点击）、自动播放的循环大动画（干扰读牌）。

## 8. 布局与响应式

- **强制横屏**：竖屏（`portrait`）显示「请横置手机」遮罩 + 手动跳过按钮（现已是）。
- 断点：`sm 640`、`md 768`、`lg 1024`、`xl 1280`、`2xl 1536`。**只用宽度断点** —— `landscape:` 变体已按 D2 移除（它在横屏下会压过宽度断点）。
- **四家牌与信息不得重叠**：1440×900 / 812×375 两档必须无溢出（本次基线已实测无溢出，改造后需重测）。
- **触控热区 ≥ 44×44**：视觉尺寸可小于 44，但热区必须补足（现做法：`after:absolute after:-inset-1.5`）。
- 安全区（D4，✅ 已完成）：`.safe-pad` 套在游戏根容器做四边内缩，手牌区另加 `var(--safe-bottom)`；组件里不再写死 `env()`。
- 结算页字号层级（D7，✅ 已完成）：主视觉「本局共得」26px 衬线，**其余 ≤16px**（番型名从 §4 的 18–22 收窄，避免抢焦点）；牌面字形不受此限（§5）。

## 9. 无障碍

- 弹窗：`role="dialog"` + `aria-modal` + 打开聚焦 + Tab 焦点循环 + Esc 关闭（已由 `src/hooks/useModalA11y.js` 落实）。
- 关键图标按钮必须有 `title` 或 `aria-label`（现状顶栏有 `title`）。
- 不允许「只用颜色」传达状态（可操作/超时/托管都要带文字或图标）。
- 触控目标 ≥44px（见上）。

## 11. 实施约定

1. **一次一个差距**：每个 PR 只做上表的一项，走「问题 / 方案 / 验证」三段式提交。
2. **token 先行**：D1 必须先做（否则每次改色都要满仓找 `#xxxxxx`）。
3. **不做的事**：不重绘牌面艺术、不换标题字体（Noto Serif SC 已定）、不引入 UI 库、不为动画加依赖。
4. **性能红线**：`npm run build` 产物体积不显著增长（当前以 CI 记录的基线为准）；动效不得掉帧（可用 Performance 面板佐证）。
