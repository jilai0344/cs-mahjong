### 计分（当前实现）

- `checkHu` 返回 `score`：平胡 = 1；大胡 = 非平胡番种数 × 6（`ML:548-554`）。
- `handleRoundWin` **重复实现**同一算法（`APP:1325-1329`），与 `checkHu` 的 `score` 并存 → 双份计分逻辑，易漂移（P2）。
- 番种可叠加计分（如“将将胡+碰碰胡”= 12 分）。
- 自摸/点炮倍数、扎鸟倍数见 §5。

## 10. 待你决策的问题清单（不得臆断，请逐条裁定）

> 每条给出：问题 / 代码现状 / 需要你给的裁定。裁定后我会同步修改测试与 README（硬性约束）。

**Q1（P0）杠上开花与含杠手牌的胡牌资格。**
现状：`checkHu` 只接受“手牌+面子恰好 14 张”，而含杠面子必然 15/16 张，导致开杠后整局无法胡牌。
裁定项：(a) 采用标准规则——1 个杠按 3 张有效牌折算（14 张有效牌即可胡），还是 (b) 保持“总张数”口径但在判定时扣除杠的多余张数，还是 (c) 其他？
（我倾向 (a)，请你确认。）

**Q2 开杠需将的精确判定。**
现状：只要剩余手牌中存在任意一张 2/5/8 即可开杠。
裁定项：(a) 保留现状；(b) 要求剩余手牌中 2/5/8 至少有一对可作将；(c) 要求 258 总数 ≥2 张（不必成对）；(d) 其他。

**Q3 起手胡口径与命名。**
现状：10 种（含 README 未列的一个五、三个五/三个八、三连对、三同、二筒二条、中途四喜），其中“大四喜”被定义为“起手 4 张相同牌”。
裁定项：(a) 是否把 README 补齐为 10 种；(b) “大四喜”是否改名（真实长沙“大四喜”为四风刻，本作无字牌）；(c) 各番型的分数是否统一为 2 分/把。

**Q4 扎鸟取牌位置。**
现状：取牌墙头部前 N 张（不影响牌墙）。
裁定项：(a) 从牌墙**末尾**取 N 张并移除（与开杠补牌同侧）；(b) 从头部取但移除；(c) 由赢家掷骰定位置；(d) 保持现状。

**Q5 扎鸟结算对象。**
现状：只算“中赢家”的鸟数，其他座位中鸟无奖惩。
裁定项：(a) 保持（中鸟只给赢家加彩）；(b) 中鸟座位也要按名次收付（真长沙常见）；(c) 其他。

**Q6 点炮赔付倍数。**
现状：点炮者独付 3 倍底分（包三家），自摸三家各付 1 倍。
裁定项：(a) 保持包三家；(b) 点炮者只付 1 倍；(c) 自摸 2 倍（真长沙常见）/点炮 1 倍；(d) 其他。

**Q7 大胡番值与叠加规则。**
现状：平胡 1 分；每个大胡番种 6 分，可叠加累加（如将将胡+碰碰胡=12 分）。
裁定项：(a) 保持“每项 6 分累加”；(b) 改为“番数 × 底分”的真实番制（并给出每种番的番数表）；(c) 是否设置封顶/最大番。

**Q8 联机规则归属与锁定。**
现状：房主的本地设置决定开局行为，不下发访客、不锁定，访客界面上看不到本局规则。
裁定项：(a) 房主设置 → 全员可见 → 开局锁定（我在 ROADMAP 里按此排期）；(b) 还是各人自选。

**Q9 一炮多响（含杠上炮）。**
现状：只结算顺位最近的一家。
裁定项：(a) 真一炮多响，多家同时胡、按各自番型分别结算；(b) 只承认顺位最近一家（现状）并修改 README；(c) 其他（如“一炮多响但赔付上限”）。

**Q10 需要新增哪些番种（README 外）。**
候选：七小对/豪华七小对、天胡/地胡、一枝花/节节高、三同（胡牌型）、金童玉女、十八罗汉。
裁定项：请勾选要做/不做的清单；不选的一律不实现。

**Q11（P1）抢杠胡与海底系列是否要做。**
现状：番种代码存在但不可达。
裁定项：(a) 补齐实现（补杠时询问其他人抢胡；牌墙最后一张牌触发海底）；(b) 删除死代码并在 README 中移除。
